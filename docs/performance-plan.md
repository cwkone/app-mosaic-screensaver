# Performance audit and implementation plan

2026-09-12. Source of truth: https://github.com/cwkone/app-mosaic-screensaver, main commit `da62bb6` (release 1.0). The former `cwkone/app-mosaic` remote is obsolete. This document is a static audit and implementation handoff, not a measured performance improvement.

## Required outcome

Reduce CPU, compositor/GPU work, memory, startup bursts, and wakeups on dense grids and multiple displays, especially the Intel i9 MacBook Pro. Preserve all visuals, artwork, preferences and migrations, controls, app selection, shuffle behavior, scrolling directions and speeds, fades, margins, colors, and preview/install behavior. No arbitrary icon-count cap, removed options, degraded resolution, or forced lower animation quality. No guarantee about fans on every Mac without hardware evidence.

## Findings

1. **Dense layer graph and independent motion.** `Sources/Renderer.swift:4-18` allocates a container and two image layers per cell, including unused incoming layers. Lines 125-147 install a perpetual position animation on each cell. At 64-point icons and 8% spacing, a stationary 1920x1080-point grid has 448 cells / 1,347 layers; 3840x2160 logical points has 1,792 cells / 5,379 layers. Scrolling adds overscan cells. These are geometry-derived counts, not measured GPU costs. Logical points must not be confused with physical display pixels.
2. **Full rebuilds without input equality checks.** `Renderer.configure` discards every layer, playback state and pending request. `MosaicView.swift:62-101` reaches it from discovery, attachment, startup, resizing and backing changes. Coalesce callbacks and distinguish geometry, palette, selection and timing changes; retain useful textures and playback state.
3. **Repeated artwork preparation and incomplete memory accounting.** `Artwork.swift:25-65` caches final textures by app path, size and color, repeating icon acquisition, normalization and rasterization across variants. Its 64 MB NSCache cost is not a total memory ceiling: visible layer textures, pending work and compositor resources are additional. Cancellation is checked before decoding, not during expensive stages. Examine cancelled/coalesced job races and nil-result readiness while changing this pipeline.
4. **Multi-display sharing stops at process boundaries.** `SharedAppCatalog` and `MosaicArtworkCache` are process-local singletons. Multiple host processes can repeat scans, decoding and caches. Confirm actual host topology before designing cross-process sharing. Discovery is user-initiated QoS and refreshes on requests after 30 seconds; avoid unnecessary rescan bursts and writes without making newly installed apps disappear indefinitely. Do not introduce a resident helper daemon without demonstrated need.
5. **Selection and UI allocations scale with collection/grid size.** `Model.swift` uses array removal and repeated pool scans for rotation, and reconstructs visible sets during replacement. Dense grids exceeding the selection pool take repeated fallback paths. `Options.swift:22-25,157,206-227` repeatedly filters the full app list during table callbacks and recomputes selection counts during visual-control edits.
6. **Validation misses the reported workload.** `Preview.swift:102-119` checks no work in frame callbacks and measures ten seconds of process CPU. This excludes WindowServer/GPU work and can overlap catalog refresh. Existing layout/palette/lifecycle tests are useful but do not establish smooth live scrolling, multiple displays or thermal behavior. Review all existing tests before extending them.

## Implementation sequence after usage reset

1. Fetch GitHub again and read AGENTS.md. Continue on a dedicated performance branch based on current main, preserving unrelated work. Reconcile this audit if upstream changed. Do not work from the stale original local main.
2. Establish bounded, reproducible baselines: cold/warm start, stationary/scrolled scenes, 64/104/256-point icons, zero/default spacing, original/tint/monochrome, large and tiny selected collections, 1/2/3 views and mixed backing scales. Record CPU time, memory, layer/animation counts, rebuilds, decodes and timer work. Profile actual awake displays and host processes when available; clearly label offscreen results and unavailable GPU/energy metrics. Capture display configuration without changing it or the user's preferences.
3. Remove redundant rebuilds; batch initial texture assignments; cancel obsolete work promptly. Reuse normalized artwork across size/color variants with bounded caches and appropriate invalidation. Improve collection bookkeeping and cache chooser filtering without changing selection semantics.
4. Prototype a renderer that composites static icons into bounded tiles or strips, uses temporary layers only for active fades, and moves groups instead of every icon independently. Preserve offscreen wrapping, unique/repeated app rules, fade-to-black timing, and edge treatments. Benchmark against simpler layer pooling/grouping before selecting the design. Avoid a full-screen bitmap redrawn every frame. Do not assume Metal or blanket layer rasterization is automatically cheaper.
5. Coordinate per-host scheduling, memory budgets and discovery across views. Test separate host processes; add persistent normalized artwork reuse only if measurements justify it, with bounded disk use and app-update invalidation. Suspend cleanly for sleep, detach, stop and display changes.
6. Run all existing checks required by AGENTS.md plus meaningful new performance/lifecycle tests and visual comparisons. Require a substantial measured reduction in the dense multi-view workload, no unexplained rebuild/decoding loop at steady state, bounded memory that releases on stop, and no feature or visual regression. Do not present synthetic frame tests as live smoothness or promise a universal fan threshold.
7. Build universal bundles and verify icon metadata, signatures and packaging. Preserve the current release and report before/after evidence and hardware limitations. Push the performance branch with the required Codex co-author trailer and provide a reviewable PR; do not replace the published release while hardware validation remains unresolved.
